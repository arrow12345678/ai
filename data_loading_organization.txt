## Document Data Loading and Organization

This section details the procedures for acquiring datasets and the proposed structure for organizing project files and data.

### Data Download Instructions

#### 1. CCPD (Chinese City Parking Dataset) - Example

The CCPD dataset is a large benchmark for LPR. As of the last update, it's often shared via cloud storage.

*   **Source Links:**
    *   The official GitHub repository ([https://github.com/detectRecog/CCPD](https://github.com/detectRecog/CCPD)) usually contains links to download the dataset. These links might point to Google Drive, Baidu Yun, or other hosting services.
    *   **Example Google Drive/Baidu Yun:** Users would typically navigate to these links, and download the compressed files (e.g., `.zip` or `.tar.gz`).
        *   `CCPD-Base`: Contains the main bulk of diverse images.
        *   `CCPD-Challenge`: May include specific challenging subsets like `CCPD-Blur`, `CCPD-FN` (Far and Near), `CCPD-Rotate`, `CCPD-Tilt`, `CCPD-Weather`.

*   **Decompression:**
    Once downloaded, these files need to be decompressed.
    *   **For `.zip` files:**
        ```bash
        unzip CCPD-Base.zip -d ./ccpd_dataset
        ```
    *   **For `.tar.gz` files:**
        ```bash
        tar -xvzf CCPD-Base.tar.gz -C ./ccpd_dataset
        ```
    *(Note: The exact filenames and directory names (`./ccpd_dataset`) should be adjusted based on the downloaded files and user preference.)*

#### 2. Downloading from Kaggle (Generic Example)

Kaggle is a popular platform for datasets. The `opendatasets` library can simplify downloading.

*   **Installation:**
    First, install the `opendatasets` library if you haven't already:
    ```bash
    pip install opendatasets --quiet
    ```

*   **Download Command:**
    In a Python script or Jupyter/Colab notebook:
    ```python
    import opendatasets as od

    # Replace 'kaggle_dataset_url' with the actual URL of the dataset on Kaggle
    # e.g., 'https://www.kaggle.com/datasets/username/dataset-name'
    dataset_url = 'kaggle_dataset_url'
    od.download(dataset_url, data_dir='./datasets')
    # This will download the dataset into a folder named after the dataset inside './datasets'
    ```

*   **Kaggle API Credentials:**
    The `opendatasets` library (and the official Kaggle API) requires your Kaggle API credentials.
    1.  **Create API Token:** Go to your Kaggle account settings (`https://www.kaggle.com/YOUR_USERNAME/account`), and click on "Create New API Token". This will download a `kaggle.json` file.
        ```json
        {"username":"YOUR_KAGGLE_USERNAME","key":"YOUR_KAGGLE_API_KEY"}
        ```
    2.  **Provide Credentials:**
        *   **Colab/Manual:** When you run `od.download()`, it will prompt you to enter your Kaggle username and API key.
        *   **Environment Setup (Recommended for local):** Place the `kaggle.json` file in the expected directory (e.g., `~/.kaggle/kaggle.json` on Linux/macOS, or `C:\Users\USERNAME\.kaggle\kaggle.json` on Windows). Ensure the file has appropriate permissions (e.g., `chmod 600 ~/.kaggle/kaggle.json`).

### Dataset Annotation Formats

#### 1. License Plate Detection (LPD) - YOLO Format

If YOLO is chosen for plate detection, annotations need to be in the YOLO format. For each image, there will be a corresponding `.txt` file with the same name (e.g., `image1.jpg` will have `image1.txt`). Each line in the `.txt` file represents one detected object (i.e., one license plate).

The format for each line is:
`<class_id> <x_center> <y_center> <width> <height>`

*   `<class_id>`: Integer representing the class of the object. For LPR, this will typically be `0` if "license_plate" is the only class.
*   `<x_center>`: Normalized x-coordinate of the center of the bounding box (relative to image width).
*   `<y_center>`: Normalized y-coordinate of the center of the bounding box (relative to image height).
*   `<width>`: Normalized width of the bounding box (relative to image width).
*   `<height>`: Normalized height of the bounding box (relative to image height).

Normalization is done by dividing the pixel values by the image width (for x_center and width) or image height (for y_center and height). All values are floats between 0 and 1.

**Example:** For an image `img001.jpg`, the annotation file `img001.txt` might contain:
`0 0.5 0.6 0.2 0.05`
This indicates one license plate (class 0) centered at (50% of width, 60% of height), with a width of 20% of the image width and a height of 5% of the image height.

#### 2. Optical Character Recognition (OCR) Data Organization

Data for the OCR model needs to be prepared differently:

*   **Input:** Typically, these are images of cropped license plates (obtained from the LPD step or manually cropped). Sometimes, individual character images are used, but sequence-based models like CRNN prefer full plate crops.
*   **Organization:**
    *   A directory like `datasets/Target_License_Plates/ocr_data/cropped_plates/` would store these image files (e.g., `plate_001.png`, `plate_002.png`).
    *   A corresponding label file (e.g., `datasets/Target_License_Plates/ocr_data/labels.txt` or `gt.txt`) would map image filenames to their ground truth text.
        **Example `labels.txt` format:**
        ```
        plate_001.png,ABC123
        plate_002.png,XYZ789
        ...
        ```
    *   For some OCR training pipelines, especially those not using CTC loss and requiring pre-segmentation, data might be organized into subfolders for each character class (e.g., `data/ocr_characters/A/char1.png`, `data/ocr_characters/B/char2.png`). However, for CRNN with CTC, the sequence-to-sequence mapping (cropped plate image to full text string) is more common.

This structured approach to data loading and organization will ensure consistency and reproducibility throughout the project lifecycle.## Document Data Loading and Organization
